Sweep browser

Finetunes are the rows (full SFT and LoRA). Mask, GRPO and restricted runs are a sparsity sweep rather than a trajectory, so they are not rows — they hang off the finetune they were fitted on, expandable in All runs.

Off-target by method × learning rate

One tile per cell, on prompts the training distribution never contained. Each grid has its own metric dropdown over everything its evals reported on that split — the headline is the default, and the companions are what separate drift from damage (undetermined_frac), grade an all-or-nothing fraction (upper_letter_frac), or read the mirror direction. Grey means the run collapsed (held-out loss above × its own step-0 value), so its behaviour number measures damage rather than drift — the number is still printed, because undetermined_frac on a grey tile is exactly how you tell the two apart. A ⋯ tile is a cell with no results yet. Click a tile to open that run beside the grid: its trajectory against every run in the same grid, and its own generations. Tasks are separate grids because the metric differs between organisms; metrics with no off-target notion (mmlu, sft_loss) appear in the dropdown under their own split.

Trajectories

Every filtered run, coloured by learning rate. Dashed grey is the pretrained anchor (step 0, before any update); the vertical dashed line is the end of warmup. The batch loss is per optimizer step, the rest are eval points.

Generations

Last eval point first. A percentage is only interpretable next to the text behind it — a run scoring 1.00 on a casing metric can be emitting one repeated syllable.

All runs

Click a header to sort. stale means config.yaml is newer than evals.json, i.e. the results predate the config and belong to an earlier attempt of the same cell. Runs with no evals.json are listed too, with every measured column empty and a running/idle status carrying the furthest eval step that wrote generations and how long ago anything was written — nothing on disk distinguishes a live job from a crashed one, so that age is a hint and squeue is the authority. w&b links the run: run ↗ is the exact run id, recorded by train/loop.py in wandb.json; find ↗ is a name search in the project, for runs finished before that file existed. A ▸ n next to a run name expands the mask, GRPO and restricted runs fitted on that finetune's delta — each one a sparsity sweep, shown as splits × frac with the held-out loss underneath.
